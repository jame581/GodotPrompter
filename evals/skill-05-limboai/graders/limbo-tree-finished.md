Pass only if the enemy script detects the end of the tree by connecting to the BTPlayer signal named `updated` (C#: the `Updated` event), which carries the tree's status, and handles the restart correctly. Either is correct: leaving the tree running, because a tree that returned SUCCESS or FAILURE re-enters from the root on the next update by itself (the answer may say so), or calling `restart()` (C#: `Restart()`) to start over explicitly. A short pause that sets `active = false` (C#: `Active = false`) and then sets it back to true is also fine. Fail if the script sets `active = false` and never re-enables the tree, since the user asked for it to start over, or if it claims a finished tree stays stopped until `restart()` is called. Fail if the code that detects the tree finishing connects to `behavior_tree_finished` (deprecated), or to any other signal name such as `finished`, `tree_finished` or `completed`. Mentioning `behavior_tree_finished` only to say it is deprecated is fine.
