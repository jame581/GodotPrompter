# v1.16.0 Implementation Plan

**Status:** shipped in v1.16.0 (2026-10-22)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.16.0: the three new skills already on `master` (web-services, rendering-pipeline, web-export) plus size headroom, eval coverage for the new skills, the deferred C# method-body checks, and a first audit of prose claims not tied to a Godot version.

**Architecture:** Documentation repo. Every task edits Markdown under `skills/`, `evals/` or `docs/`, and is checked with `node scripts/validate-skills.mjs`, `npm test`, the Godot 4.7.2 binary (`godot`) and `dotnet` with `Godot.NET.Sdk/4.7.2`. Throwaway check harnesses live in the session scratchpad, not the repo; their results are recorded in a research note.

**Tech Stack:** Markdown skills, Node validator, Godot 4.7.2 headless, .NET 9 + `Godot.NET.Sdk` 4.7.2, `claude plugin eval`.

**Spec:** the scope agreed in the 2026-10-21 session (no separate spec file):
1. Pattern X moves for the two near-cap new skills (`web-services` 15800 B, `rendering-pipeline` 15633 B).
2. Release counts: manifests, `docs/token-budget.md`, README validator baseline.
3. One eval case per new skill.
4. Follow-up 7(b): the 93 C# blocks not checked to method bodies, plus the "name does not exist" filter gap.
5. Follow-up 7(c): prose claims not tied to a version.
6. Pattern X moves for `shader-basics` (15344 B) and `input-handling` (15268 B).
7. Release branch, PR, tag.

## Global Constraints

- Target Godot 4.3+; no deprecated methods. Facts are checked against tags `4.3-stable` and `4.7.2-stable` (`ed1daf0b`).
- SKILL.md target after a Pattern X move: **≤ 14,500 B** (validator count; warning at 15,872, error at 16,384). Target headroom, not a uniform byte count.
- Every GDScript example keeps a C# equivalent, except `web-export` (C# cannot export to Web in Godot 4) and the existing `csharp-parity: n/a` exemptions.
- Corrections are swept, not patched (follow-up 7(d)): after correcting a claim, grep `skills/`, `agents/`, `.codex/` for its key nouns.
- Never hand-edit `skills/index.json` or `.codex/agents/godot-prompter/*.toml`; run `npm run build:skill-index` / `npm run sync:codex-agents`.
- Never quote a risky approval/sandbox mode literally in any `.md/.json/.toml/.yml` file (plugin-scan).
- Content an eval grader measures stays inline in SKILL.md, not in a reference (e.g. `input-handling` §9 device-ID warning, line ~294, measured by `skill-12-input-device-ids`).
- Commit messages end with the Co-Authored-By line; no model name elsewhere.
- **Execution order: 1, 2, 4, 3, 5, 6** — the C# checks (Task 4) can touch the new skills, so the evals (Task 3) run after them. Task 5 does not touch the three new skills.
- **No SKILL.md may cross 15,500 B** in any task. A skill an edit would push over gets a Pattern X move in the same commit first.
- **Note filenames** use the date of the commit that creates them (`2026-MM-DD-…`), not `xx`.
- **Reference files** follow the existing shape (see `skills/web-services/references/rest-client-patterns.md:1-5`): an H1, a `Reference for \`skills/<s>/SKILL.md\` — …` line, `> ← Back to [SKILL.md](../SKILL.md)`. SKILL.md links them inline (`> See [references/x.md](references/x.md) for …`); there is no references list and the Related-skills line is for skills only.
- **Link check** (the validator does not resolve reference links; it only warns `orphan-reference`): for each touched skill run `grep -o 'references/[a-z0-9-]*\.md' skills/<s>/SKILL.md | sort -u | while read f; do test -f "skills/<s>/$f" || echo MISSING $f; done` → no output, and the validator gains no `orphan-reference` warning.
- Branch: `release/v1.16.0` from `master`. One commit per task. The PR goes to `master`; Jan merges it and the marketplace PRs.

## Review Focus

1. **A moved section loses a fact the summary still promises, or a link breaks** — every link from SKILL.md to a reference resolves (the link check in Global Constraints; the validator does not do it), every inbound pointer from another skill to a moved section is repointed, and every fact named in the summary appears in the reference. Each Pattern X task diffs the removed lines against the reference.
2. **A "correction" from the prose audit is itself wrong** — every changed claim cites a source file and line at a tag in the research note; a claim that cannot be cited is softened, not asserted.
3. **An eval case that does not discriminate** — each new case runs with `--ablation with-without`; a case where both arms score ≥ 0.9 is tagged `ceiling`, not `discriminating`.
4. **C# stubs that hide real errors** — stubs only define user/addon types; no engine type is stubbed, and the "name does not exist" (CS0103) errors are reviewed, not filtered.
5. **Stale counts after the release bump** — `grep -rn "56 skills\|56 domain"` across manifests and docs returns nothing (CHANGELOG and dated specs/plans excepted).
