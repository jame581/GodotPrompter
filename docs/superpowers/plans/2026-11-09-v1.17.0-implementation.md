## Timing gate: Godot 4.8 is not stable yet

As of 2026-11-09 the newest 4.8 build is `4.8-beta2` (2026-10-29, `godotengine/godot-builds`). 4.7 went from beta to stable in roughly a month, so 4.8-stable is expected around December 2026.

- **Phases A and B do not depend on 4.8.** Start them now.
- **Phase C (the 4.8 inventory) runs against the newest beta or RC.** Every row records the build it was checked on.
- **Phase D (apply) may start on an RC.** Once `4.8-stable` is tagged, every applied row must be re-checked against that tag. Do not tag v1.17.0 before then.
- If 4.8-stable slips well into 2027, ship A and B as **v1.17.0** and move the 4.8 pass to v1.18.0. Decide this at the end of Phase B.

## Global Constraints

- The minimum stays **Godot 4.3+**. Every 4.8 addition is annotated `(Godot 4.8+)`, or carries a `Changed in Godot 4.8` warning when behaviour changes. Nothing that works in 4.3 to 4.7 is removed or replaced without a version callout. Precedent: `add_dock` vs `add_control_to_dock`.
- **Facts are checked against source:** the engine tag (`4.8-stable`, or the named beta/RC while it is pending), the godot-docs class reference, and the migration guide `upgrading_to_godot_4.8.rst`. A claim with no citation is dropped or softened, never asserted. Rule from the 4.7 pass: `2026-10-11-godot-4.7-callout-audit.md` had to correct claims the deltas note asserted from changelog PR titles alone.
- **Addon facts are checked against the addon's release tag**, not its docs site (CONTRIBUTING's addon conventions). Each skill's pinned version line names the tag and the Godot range it supports.
- C# parity per **authoring-godot-prompter-skills**. Dialogue Manager ships C#. LimboAI, Beehave, Phantom Camera and Popochiu keep their existing parity decisions unless the release changed what they ship.
- **No SKILL.md may cross 15,500 B in any task.** If an edit would push a skill over, that skill gets a Pattern X move in the same commit first. `export-pipeline` (15,342) and `physics-system` (15,242) need the move **before** any 4.8 row lands in them.
- **Corrections are swept, not patched:** after changing a claim, grep `skills/`, `agents/`, `.codex/` and `evals/` for its key nouns.
- **The session card has 1 byte of headroom** (3,071 of 3,072 B). Do not touch the `SESSION-CARD` region in this release unless a task frees bytes first and re-baselines grill-05 at 5 runs per arm.
- Never hand-edit `skills/index.json` or `.codex/agents/godot-prompter/*.toml`. Run `npm run build:skill-index` and `npm run sync:codex-agents`.
- Never quote a risky approval or sandbox mode literally in any `.md`, `.json`, `.toml`, `.yml` or `.yaml` file (plugin-scan).
- Note filenames use the date of the commit that creates them.
- Branch: `release/v1.17.0` from `master`. One commit per task, pushed as it lands. The PR goes to `master`. Jan merges it and the marketplace PRs.

## Review Focus

1. **A 4.8 claim asserted from a changelog title or a beta, not from the stable tag.** Every applied row cites a file and line at `4.8-stable`.
2. **An addon skill that still teaches the old major version.** Dialogue Manager 3 → 4 renamed titles to *cues*. Grep every addon skill, its eval case and its graders for the old terms.
3. **A version callout that breaks 4.3 to 4.7 users.** A new API must sit next to the old one, not replace it.
4. **An eval grader still checking for removed wording.** Re-run every addon case and the new 4.8 case with `--ablation with-without`.

## Phase F: Skill over-triggering and token cost (discussion #18)

Added 2026-11-11. Phase C runs in parallel in a separate worktree (`../GodotPrompter-phase-c`, branch `v1.17.0-phase-c`, merged back into `release/v1.17.0` when C is done), because F edits many skill files and C writes a notes file and the `godot-mentor` references.

**The report (#18):** about 60% of one user's tokens went to GodotPrompter skills. Agents loaded `inventory-system` and `ability-system` because the project is an RPG, although both systems already exist in the project and are more complex than the skills' patterns. `godot-brainstorming` fired constantly, under Codex in particular, even for changes that do not touch Godot. The user also asked whether individual skills can be turned off.

**Causes found on 2026-11-11 (to confirm in F1):**
- The session card's rule says "before implementing any Godot system, invoke the matching skill". Its red-flag table includes "I loaded a Godot skill already → different system, different skill". Nothing in the card says when **not** to load a skill.
- `AGENTS.md` (Codex) and `GEMINI.md` @-import all of `using-godot-prompter/SKILL.md` (14,560 B, about half of it install instructions) into every session. `AGENTS.md` also imports `copilot-tools.md`.
- Gameplay-system descriptions ("Use when building inventory systems") match any project of that genre. Nothing in them separates "build a new X" from "work inside an existing X".
- The descriptions add up to 8,910 characters. Every session on every host pays for them. `web-services` grew to 415 in Task B3.

**Success criteria (measured in F6 against F1):**
- In the new negative cases, the named domain skill fires at most 1 of 3 times and `godot-brainstorming` fires 0 of 3.
- No positive routing case (skill-01 to skill-18, grill-01, grill-04, grill-05) loses more than one fire out of three compared with its F1 baseline.
- The bytes injected per session on Codex and Antigravity drop by at least 40%.
