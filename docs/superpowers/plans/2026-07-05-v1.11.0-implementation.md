# GodotPrompter v1.11.0 Implementation Plan — "Godot 4.7 Alignment"

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align all 51 skills, 9 agents, and repo docs with Godot 4.7 (released 2026-06-18) via a verified per-skill delta inventory followed by a skill-by-skill apply pass — no new skills, minimum stays Godot 4.3+.

**Architecture:** Two phases replaying the v1.5.0 alignment method. Phase 1 (Tasks 1–3) authors `docs/superpowers/notes/2026-07-05-godot-4.7-deltas.md`, where every row is verified against the local godot-docs clone or engine CHANGELOG before inclusion. Phase 2 (Tasks 4–18) applies rows skill-cluster by skill-cluster in impact order, checking rows off as applied. Tasks 19–20 update README/agents and cut the release.

**Tech Stack:** Markdown (SKILL.md), GDScript 2.0, C# (Godot bindings), Node.js validator (`scripts/validate-skills.mjs`). Grounding sources: `D:/Godot/godot-docs` (master; includes 4.7 class reference + `tutorials/migrating/upgrading_to_godot_4.7.rst`) and `D:/Godot/godot/CHANGELOG.md` (§ "4.7 - 2026-06-18").

**Spec:** `docs/superpowers/specs/2026-07-05-v1.11.0-design.md`

## Global Constraints

Every task implicitly includes these. Copy them into your working context before editing.

1. **Repo-wide minimum stays Godot 4.3+.** All 4.7 content is additive and annotated; never rewrite an existing 4.3-valid example to use a 4.7 API.
2. **Annotation format** (matches existing 4.5/4.6 style): new sections titled `### N.x Feature Name (Godot 4.7+)` or, inside an existing section, a note line starting `> **Godot 4.7+:** …`.
3. **Behavior-change warning format** (for silent 4.7 changes):
   ```markdown
   > ⚠️ **Changed in Godot 4.7:** <one-sentence what changed>. <one-sentence how to fix/migrate>. See the [4.7 migration guide](https://docs.godotengine.org/en/latest/tutorials/migrating/upgrading_to_godot_4.7.html).
   ```
4. **GDScript first, then C#** (` ```gdscript ` then ` ```csharp `) within every new section, unless the skill is on the validator's GDScript-only allowlist (`gdscript-patterns`, `gdscript-advanced`, `beehave`).
5. **Grounding rule:** every API name, signature, enum value, and default in new content is copied from the cited `.rst` under `D:/Godot/godot-docs/classes/` (or the migration guide), never from memory. If the `.rst` contradicts the inventory row, fix the row and note it.
6. **Experimental policy:** Vulkan raytracing and `DrawableTexture2D` get mention-only lines ("experimental in 4.7, not yet recommended for production"), no code recipes.
7. **Validator gate:** after every task, `node scripts/validate-skills.mjs` must end with exactly `0 error(s), 13 warning(s).` — the 13 are pre-existing `csharp-parity-accepted`. Any new warning is fixed in the same task (for `token-budget-exceeded`, apply Pattern X: move a deep-dive to `skills/<name>/references/<topic>.md` with a `> ← Back to [SKILL.md](../SKILL.md)` header and a 2–3 sentence summary + link left behind).
8. **Inventory checkoff:** after applying a row, append ` [done]` to its Source cell in the inventory note (same convention as the 4.5/4.6 note). Rows deliberately not applied get ` [dropped: <reason>]`.
9. **Commits:** one commit per task, on branch `feature/v1.11.0`, message format `docs(<skill|scope>): <summary> (godot 4.7)`.
10. **Cross-references:** any `**skill-name**` mention added must be a real skill folder; the validator enforces this.
