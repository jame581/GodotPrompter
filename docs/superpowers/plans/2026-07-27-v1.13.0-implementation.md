# GodotPrompter v1.13.0 "Presence & Mentor" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make GodotPrompter's domain skills reliably invoked in Godot projects by injecting a routing card at SessionStart, and add a persistent mentor mode that teaches while building.

**Architecture:** A conditional SessionStart hook detects `project.godot`, extracts a delimited "session card" region from the bootstrap skill, and injects it as `additionalContext`. The card is a *region inside* `using-godot-prompter/SKILL.md`, never a copy, so it cannot drift. A new `godot-mentor` skill wraps existing domain skills in a five-beat teaching contract, persisted to `.godot-prompter/config.json` in the user's project and restored by the same hook.

**Tech Stack:** Bash (hook), Node 20 ESM (validator, tests via built-in `node:test`), Markdown (skills). No new runtime dependencies.

## Global Constraints

- **Godot baseline:** 4.3+ repo-wide. Do not raise it. Addon skills keep their own higher minimums.
- **Token budget:** every `skills/*/SKILL.md` must stay **under 16,384 bytes** (LF-normalized) — validator *error*, fails CI. Advisory *warning* at 15,872 bytes.
- **Session/mentor card cap:** 3,072 bytes (LF-normalized) per card region.
- **Zero bytes added to existing domain skills.** 8 skills have < 100 bytes of headroom. Only `using-godot-prompter` (which has room) and new files may grow.
- **Example convention:** GDScript block first, then the C# equivalent, within the same numbered section.
- **Skill naming:** kebab-case folder; `SKILL.md` frontmatter `name` must equal the folder name.
- **Version lockstep — all five files** must equal the tag: `package.json`, `plugin.json` (root/Antigravity), `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `.cursor-plugin/plugin.json`. `release.yml` fails the release on drift.
- **Two hook directories, do not conflate:**
  - `scripts/hooks/` — **existing repo development tooling** (`validate-skill-on-edit.mjs`, wired via `.claude/settings.json`). Leave it alone.
  - `hooks/` (root, new) — **shipped plugin hooks** that run on the plugin *user's* machine.
- **Attribution:** files adapted from Superpowers (MIT, Jesse Vincent) carry a header comment saying so.
- **Validator must stay at 0 errors** on `node scripts/validate-skills.mjs`. The 16 accepted `csharp-parity-accepted` warnings are the expected baseline; do not "fix" them.
- **Commit style:** Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`).

```js
function validateCard(path, markerName, budgetBytes) {
  const content = readFileSync(path, 'utf8').replace(/\r\n/g, '\n');
  const start = `<!-- ${markerName}-START -->`;
  const end = `<!-- ${markerName}-END -->`;
  const si = content.indexOf(start);
  const ei = content.indexOf(end);

  if (si === -1 || ei === -1) {
    const missing = si === -1 ? start : end;
    record(errors, path, 'card-marker-missing', `Missing ${missing} — the SessionStart hook injects this region`);
    return;
  }
  if (ei < si) {
    record(errors, path, 'card-marker-malformed', `${end} appears before ${start}`);
    return;
  }
  const region = content.slice(si + start.length, ei).trim();
  if (region.length === 0) {
    record(errors, path, 'card-empty', `Region between ${start} and ${end} is empty — the hook would inject nothing`);
    return;
  }
  const bytes = Buffer.byteLength(region, 'utf8');
  if (bytes > budgetBytes) {
    record(errors, path, 'card-oversized', `${markerName} region is ${(bytes / 1024).toFixed(1)} KB (cap: ${budgetBytes / 1024} KB) — it is injected on every session start and compaction`);
  }
}
```

Create `hooks/session-start`:

```bash
#!/usr/bin/env bash
# SessionStart hook for the GodotPrompter plugin.
#
# Fires only inside a Godot project (project.godot found within 4 levels up from CWD);
# elsewhere it is a silent no-op. Injects the SESSION-CARD region from the bootstrap skill,
# plus the detected Godot version/renderer, plus the MENTOR-CARD region when mentor mode is on.
#
# Adapted from the Superpowers plugin (MIT, Jesse Vincent) — the JSON escaper and the
# three-way platform output branching originate there. https://github.com/obra/superpowers

set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PLUGIN_ROOT="$(cd "${SCRIPT_DIR}/.." && pwd)"

# --- 1. Locate the Godot project (CWD, then up to 4 ancestors) ------------------------------
find_godot_project() {
  local dir="$PWD" depth=0 parent
  while [ "$depth" -le 4 ]; do
    if [ -f "${dir}/project.godot" ]; then
      printf '%s' "$dir"
      return 0
    fi
    parent="$(dirname "$dir")"
    [ "$parent" = "$dir" ] && break
    dir="$parent"
    depth=$((depth + 1))
  done
  return 1
}

PROJECT_ROOT="$(find_godot_project)" || exit 0

# --- 2. Extract a marked card region from a skill file ---------------------------------------
extract_card() {
  local file="$1" marker="$2"
  [ -f "$file" ] || return 0
  sed -n "/<!-- ${marker}-START -->/,/<!-- ${marker}-END -->/p" "$file" \
    | sed '1d;$d'
}

SESSION_CARD="$(extract_card "${PLUGIN_ROOT}/skills/using-godot-prompter/SKILL.md" 'SESSION-CARD')"
[ -z "$SESSION_CARD" ] && exit 0

# --- 3. Detect Godot version and renderer from project.godot ---------------------------------
# config/features=PackedStringArray("4.5", "Forward Plus")
GODOT_VERSION=""
GODOT_RENDERER=""
if features_line="$(grep -m1 '^config/features=' "${PROJECT_ROOT}/project.godot" 2>/dev/null)"; then
  tokens="$(printf '%s' "$features_line" | grep -o '"[^"]*"' | tr -d '"' || true)"
  GODOT_VERSION="$(printf '%s\n' "$tokens" | sed -n '1p')"
  GODOT_RENDERER="$(printf '%s\n' "$tokens" | sed -n '2p')"
fi

VERSION_LINE=""
if [ -n "$GODOT_VERSION" ]; then
  VERSION_LINE="This project targets **Godot ${GODOT_VERSION}**"
  [ -n "$GODOT_RENDERER" ] && VERSION_LINE="${VERSION_LINE} (${GODOT_RENDERER} renderer)"
  VERSION_LINE="${VERSION_LINE}. Prefer APIs and advice valid for that version and renderer."
fi

# --- 4. Mentor mode -------------------------------------------------------------------------
MENTOR_CARD=""
CONFIG="${PROJECT_ROOT}/.godot-prompter/config.json"
if [ -f "$CONFIG" ] && grep -q '"mode"[[:space:]]*:[[:space:]]*"mentor"' "$CONFIG"; then
  MENTOR_CARD="$(extract_card "${PLUGIN_ROOT}/skills/godot-mentor/SKILL.md" 'MENTOR-CARD')"
fi

# --- 5. Assemble and emit --------------------------------------------------------------------
escape_for_json() {
  local s="$1"
  s="${s//\\/\\\\}"
  s="${s//\"/\\\"}"
  s="${s//$'\n'/\\n}"
  s="${s//$'\r'/\\r}"
  s="${s//$'\t'/\\t}"
  printf '%s' "$s"
}

payload="${SESSION_CARD}"
[ -n "$VERSION_LINE" ] && payload="${payload}"$'\n\n'"${VERSION_LINE}"
[ -n "$MENTOR_CARD" ] && payload="${payload}"$'\n\n'"${MENTOR_CARD}"

context="<EXTREMELY_IMPORTANT>\n$(escape_for_json "$payload")\n</EXTREMELY_IMPORTANT>"

if [ -n "${CURSOR_PLUGIN_ROOT:-}" ]; then
  printf '{\n  "additional_context": "%s"\n}\n' "$context" | cat
elif [ -n "${CLAUDE_PLUGIN_ROOT:-}" ] && [ -z "${COPILOT_CLI:-}" ]; then
  printf '{\n  "hookSpecificOutput": {\n    "hookEventName": "SessionStart",\n    "additionalContext": "%s"\n  }\n}\n' "$context" | cat
else
  printf '{\n  "additionalContext": "%s"\n}\n' "$context" | cat
fi

exit 0
```

````markdown
# Godot Mentor Mode

> **Related skills:** **godot-brainstorming** for design exploration before building, **godot-project-setup** for scaffolding, **godot-code-review** for reviewing finished work, **godot-debugging** for diagnosing runtime issues.

Mentor mode changes the **shape** of an answer, not its **source of truth**. It wraps the
domain skills — it never replaces them.

## 1. The wrapping rule

**Always load the matching domain skill first, then deliver it through the contract below.**

```
"add double jump"  +  mentor mode
   1. invoke godot-prompter:player-controller   <- still authoritative
   2. deliver its guidance through the 5 beats  <- what mentor mode adds
```

Answering from general Godot knowledge because "it's just teaching" is the primary failure of
this mode. The routing table in `using-godot-prompter` still applies in full.

## 2. The five beats

<!-- MENTOR-CARD-START -->
**Mentor mode is ACTIVE for this project.** Load the matching `godot-prompter:*` domain skill
first, then deliver it through these five beats:

1. **Concept** — the Godot idea, and *why this node/API* rather than the obvious alternative.
2. **Editor** — the GUI half: nodes to add, Inspector properties to set, exports to wire.
3. **Code** — annotated GDScript, then the C# equivalent.
4. **Verify** — run it: what should happen, the likeliest failure, and the fix.
5. **Next** — *one* suggested extension. Not five.

**Editor beat boundary (v1.13.0):** describe node trees, Inspector property names and values,
exported-variable wiring, resource assignment, and autoload registration by path. Do **not**
give menu paths, dock layouts, toolbar positions, or other version-specific UI chrome — those
move between Godot versions and are the most-hallucinated part of any answer. If a click-path
is genuinely required, say which panel it lives in and let the user find it.

**Explanation, not scope.** Explain what was asked for. Do not add features in order to have
more to teach.

**Off-ramp.** "just give me the code" / "skip the explanation" → drop to normal delivery and
set `"mode": "normal"` in `.godot-prompter/config.json`.
<!-- MENTOR-CARD-END -->

## 3. Turning it on and off

On activation, write `.godot-prompter/config.json` in the **project root**:

```json
{
  "mode": "mentor",
  "level": "beginner",
  "language": "gdscript",
  "godot_version": "4.5",
  "renderer": "Forward Plus"
}
```

| Key | Values | Meaning |
|---|---|---|
| `mode` | `mentor` \| `normal` | Whether the five beats apply |
| `level` | `beginner` \| `intermediate` | How much of Beat 1 and Beat 2 to spell out |
| `language` | `gdscript` \| `csharp` | Which example leads |
| `godot_version` | e.g. `4.5` | Read from `project.godot` `config/features` |
| `renderer` | e.g. `Forward Plus` | Ditto — changes what advice is valid |

Ask for `level` **once**, on activation, then remember it. Never re-ask each turn.

Merge into the file if it already exists; never clobber unrelated keys. The file is safe to
commit (a team can share a teaching level) — mention that once and offer to `.gitignore` it if
the user prefers it personal. Do not decide for them.

The SessionStart hook re-reads this file, so mentor mode survives `/clear`, compaction, and
subagent dispatch. On Codex and Antigravity (no hook support) this skill still works; it just
does not self-restore after a context reset.

## 4. Calibrating depth

| `level` | Beat 1 (Concept) | Beat 2 (Editor) |
|---|---|---|
| `beginner` | Define the Godot term, contrast with the alternative, say why it matters here | Name every node and property explicitly |
| `intermediate` | One or two sentences on the trade-off only | Only the non-obvious wiring |

`level` controls **how much** of each beat appears — never **whether** it appears.

## 5. Anti-patterns

| Anti-pattern | Why it is wrong | Instead |
|---|---|---|
| Answering without loading the domain skill | Loses verified, version-checked guidance | Invoke the skill, then teach it |
| Inventing menu paths so the Editor beat feels complete | Godot's UI moved between 4.3 and 4.7; wrong click-paths are worse than none for a beginner | Node/Inspector level only |
| Growing the feature to create teaching material | The user asked for one thing | Explain that thing; put the rest in Beat 5 |
| Re-asking `level` every turn | Feels like the agent has amnesia | Read it from config |
| Five "next steps" | Paralyses a learner | Exactly one |
| Skipping the C# example because it is a teaching answer | C# parity is a repo-wide promise | GDScript first, then C# |

## 6. Worked example

**User:** "teach me as we go — I want the player to double jump"

**Beat 1 — Concept.** Godot's `CharacterBody2D` has no built-in jump counter. Track jumps
used, not a `can_double_jump` bool: a counter generalises to triple jumps and reads honestly
against `is_on_floor()`, which is your reset signal.

**Beat 2 — Editor.** No new nodes. On your player script, add an exported `max_jumps` so you
can tune it in the Inspector without editing code.

**Beat 3 — Code.**

```gdscript
extends CharacterBody2D

@export var max_jumps: int = 2
@export var jump_velocity: float = -400.0

var _jumps_used: int = 0

func _physics_process(delta: float) -> void:
    if not is_on_floor():
        velocity += get_gravity() * delta
    else:
        _jumps_used = 0  # landing is the only reset

    if Input.is_action_just_pressed("jump") and _jumps_used < max_jumps:
        velocity.y = jump_velocity
        _jumps_used += 1

    move_and_slide()
```

```csharp
using Godot;

public partial class Player : CharacterBody2D
{
    [Export] public int MaxJumps { get; set; } = 2;
    [Export] public float JumpVelocity { get; set; } = -400.0f;

    private int _jumpsUsed;

    public override void _PhysicsProcess(double delta)
    {
        Vector2 velocity = Velocity;

        if (!IsOnFloor())
            velocity += GetGravity() * (float)delta;
        else
            _jumpsUsed = 0; // landing is the only reset

        if (Input.IsActionJustPressed("jump") && _jumpsUsed < MaxJumps)
        {
            velocity.Y = JumpVelocity;
            _jumpsUsed++;
        }

        Velocity = velocity;
        MoveAndSlide();
    }
}
```

**Beat 4 — Verify.** Run the scene: you should get two jumps, then nothing until you land.
If you get infinite jumps, `is_on_floor()` is reporting true mid-air — your collision shape is
probably overlapping the floor. If the second jump feels weak, you are adding to a falling
`velocity.y`; assign it rather than accumulating (this code already assigns).

**Beat 5 — Next.** Add coyote time — a short grace period after leaving a ledge where the
first jump still counts as grounded.
````
