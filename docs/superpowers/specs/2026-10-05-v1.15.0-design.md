# GodotPrompter v1.15.0 — "Editor Beat"

**Status:** shipped in v1.15.0 (2026-10-06)

**Date:** 2026-10-05
**Baseline:** v1.14.1 (56 skills, validator 0 errors / 53 warnings, 2 of them real parity gaps)
**Target:** 56 skills, validator 0 errors / 51 warnings, no new skill

---

## Problem

v1.13.0 shipped mentor mode with a deliberately capped Editor beat: node trees and Inspector
properties only, no menu paths, because unresearched click-paths are the most-hallucinated part
of any Godot answer. The research that lifts the cap was deferred to v1.14.0 and then to
v1.15.0. A learner who asks "where do I click?" still gets "find the panel yourself".

Four smaller items from `docs/superpowers/notes/2026-07-28-v1.13.0-followups.md` ride along:
five skills sit inside the byte-budget warning band, no CI job exercises the Windows hook path,
the Cursor hook command is fragile and unverified, and two Android sections lack C#.

## Goals

1. Mentor mode gives click-paths that are verified per Godot version, and still refuses to
   invent one.
2. The five tightest skills regain byte headroom without losing content.
3. The Windows hook mitigations are gated by CI.
4. The Cursor hook command is robust to the documented Cursor behaviour.
5. The last two real C# parity warnings are closed.

## Non-goals

- No new skill, agent, or hook behaviour.
- No end-to-end claim for Cursor or for Android C#: neither can be run from the authoring
  environment. Both ship labelled as unverified at runtime (see D and E).
- No change to the 16 KB budget or to the budget's scope (references stay unbudgeted).
- GodotSteam, Dialogic, raytracing, and the migration meta-skill stay deferred.

## A. Mentor editor references

### Files

```
skills/godot-mentor/references/
  editor-navigation.md   docks, main-screen tabs, bottom panels, Project Settings tabs;
                         version-flagged 4.3 -> 4.7
  editor-recipes.md      ~20 workflows as numbered click-paths
docs/superpowers/notes/
  2026-10-05-godot-editor-research.md   what was verified, against which source, per version
```

### Recipe list

Add a node and attach a script; instance a scene; create a custom Resource and assign it;
connect a signal from the Node dock; add a node to a group; register an autoload; add an Input
Map action and binding; set the main scene; change window size and stretch mode; set physics
layer names; author an AnimationPlayer track and key a property; create SpriteFrames for
AnimatedSprite2D; create a TileSet and paint a TileMapLayer; change an import preset and
reimport; create a Theme and assign it; add a translation file; install and enable an addon;
create an export preset and install export templates; inspect the remote scene tree while
running; enable Visible Collision Shapes and use the profiler.

The list may shrink: a recipe whose steps cannot be verified for every version 4.3 to 4.7 is
dropped and recorded in the digest, not written from memory.

### Research standard

- Source of truth is the `godotengine/godot-docs` repository at branches `4.3`, `4.4`, `4.5`,
  `4.6`, `4.7`, read as raw `.rst`. Where the docs are silent or ambiguous, the engine source
  at the matching tag (`editor/` menu and dock registration strings) decides.
- A UI claim that is identical across all five branches is written unflagged. A claim that
  differs is written with a version flag (`4.6+: ...`, `4.3-4.5: ...`).
- A claim confirmed in neither source is omitted. The digest lists every omission.
- Existing inputs: `2026-07-05-godot-4.7-deltas.md`, `2026-04-30-godot-4.5-4.6-deltas.md`.

### Format

Each recipe: a heading, a one-line "when", numbered steps naming the exact panel, menu, or
button label in bold, version flags inline, and a "you should see" line. No code blocks, so C#
parity does not apply. `editor-navigation.md` is tables: area, what lives there, how to reopen
it if closed, version notes.

### Relaxing the boundary

The `MENTOR-CARD` region in `skills/godot-mentor/SKILL.md` replaces the "Editor beat boundary
(v1.13.0)" paragraph with a rule of this shape:

> **Editor beat: click-paths come from the references, never from memory.** Before giving a
> menu path, dock location, or button name, invoke `godot-prompter:godot-mentor` and read its
> `references/editor-recipes.md` or `references/editor-navigation.md`, and use what it says for
> the project's Godot version. If the references do not cover it, name the panel and stop.

The card names the skill to invoke because the hook injects the card alone: after `/clear` the
agent has no skill directory to resolve a bare relative path against.

The card must stay under the 3 KB cap (currently 1,756 bytes). Matching edits: the SKILL.md
body gains a short section linking both references; the "Inventing menu paths" anti-pattern row
and the checklist line are reworded to "click-path not taken from the references"; the worked
example is unchanged.

### Tests and evals

- `tests/agent-integration/TEST_PLAN.md` Test 5.2 is reworded: the expected answer now includes
  the documented path for registering an autoload; pass criteria stay "no fabricated
  click-path", with fabricated defined as "not present in the references".
- The mentor eval grader that fails any top-menu path (a regex) becomes an `llm` grader that
  fails toolbar positions, coordinates, and menu items that do not exist. It reads only the
  answer, so it cannot check paths against the reference files themselves; it judges against
  the menu, dock, and panel names listed in its own prompt. `evals/FOLLOWUPS.md` records that
  limit and that figures for the grader are not comparable across the change.
- The mentor eval itself (~50 min, ~$15) is **not** run as part of implementation. It is the
  maintainer's post-merge check; `evals/FOLLOWUPS.md` gets a "pending run" entry.

## C. Windows CI job

`.github/workflows/validate.yml` gains a second job, `hooks-windows`, on `windows-latest`:
checkout, setup-node 26, `npm run test:hooks`. Same pinned action SHAs as the existing job,
`persist-credentials: false`, 10-minute timeout. It runs only the hook suite, since that is
where the Windows-specific mitigations live.

This job cannot be run locally. `validate.yml` runs on pull requests and on pushes to `master`
only, so its first run is on the release pull request; a red result there is fixed on the
branch before the release is considered ready.

## D. Cursor hook hardening

Research Cursor's plugin and hooks documentation for: the working directory of a plugin hook
command, the environment variables it receives (the hook script already branches on
`CURSOR_PLUGIN_ROOT`), and the shell used on Windows. Then change
`hooks/hooks-cursor.json` to the most robust form the documentation supports, preferring an
absolute plugin-root path with quoting over the current relative `./hooks/run-hook.cmd`. If the
documentation supports no better form, the file stays as is and the note says so. A first read
of Cursor's docs suggests this is the likely outcome: plugin-root expansion is documented for
the MCP config only, and neither the working directory nor the Windows shell is stated for
plugin hooks.

The research also records whether `CURSOR_PLUGIN_ROOT` is exported to hook processes, because
`hooks/session-start` picks Cursor's output shape from it. If it is not documented, that goes
in the follow-ups as an open risk; the hook itself is not changed in this release.

Add a hook test pinning the Cursor command to a space-safe shape. Update follow-ups section 3 to
"hardened against documented behaviour on 2026-10-05; not run in Cursor". It is not marked
resolved.

## E. Android C# parity

Add C# blocks to "Android v2 plugins (Godot 4.2+)" and "JavaClassWrapper & AndroidRuntime
(Godot 4.4+)" in `skills/mobile-development/references/plugins.md`, derived from the documented
GDScript API: `Engine.HasSingleton` / `Engine.GetSingleton`, and `Call(...)` on the returned
`GodotObject` because C# has no dynamic member dispatch. Every class and method name is checked
against the 4.4+ class reference.

Each block is preceded by a one-line note that it has not been run on a device. The parity debt
notes and follow-ups section 5 record the same. This reverses the 2026-07-31 decision to leave
them open; the maintainer chose to ship them labelled.

## Release mechanics

- Branch `release/v1.15.0`; one commit per item (A may be several: digest, references, skill
  relaxation, tests).
- `node scripts/validate-skills.mjs` and `npm test` pass before every commit. Expected
  baseline at the end: 0 errors / 51 warnings.
- The local HOL plugin scan and `claude plugin validate` run before the version bump, if the
  tools are present in the environment.
- Changelog entry and version bump follow the `releasing-godot-prompter` skill.
- `docs/superpowers/notes/` gets a `2026-10-05-v1.15.0-followups.md` carrying what remains
  open (Cursor end-to-end, Android device test, the pending mentor eval run); `CLAUDE.md`'s
  pointer to the follow-ups file is updated.
- The implementer pushes the branch and opens a pull request to `master`, which is what runs
  CI. **Merging and tagging are the maintainer's.** The tag triggers `release.yml` and
  marketplace PRs.

## Risks

| Risk | Mitigation |
|---|---|
| A wrong click-path ships with the authority of a "verified" reference | Per-version source check, omit-if-unconfirmed, digest of what was and was not verified |
| The relaxed card makes mentor answers invent paths outside the references | The rule is "from the references or name the panel"; Test 5.2 and the eval grader hold the line |
| The references grow stale at Godot 4.8 | Version flags make the staleness local; the digest names the source branch per claim |
| Windows job is red on first run | Fixed on the branch; the release waits on it |
| Untested Cursor command breaks a working install | Change only to a form the documentation states; otherwise leave the file alone |
| Untested Android C# misleads a reader | Visible "not device-tested" note on each block |
| Pattern X move drops or splits a GDScript/C# pair | Verbatim moves; the validator's reference parity check catches a split |

## Success criteria

- Both reference files and the digest exist; every versioned claim in the references traces to
  a line in the digest.
- Mentor card under 3 KB; validator 0 errors / 51 warnings; `npm test` green.
- All five Pattern X skills under the 15,872 warning line with recorded headroom.
- `hooks-windows` job green on the release pull request.
- Changelog and version at 1.15.0; tag left for the maintainer.
