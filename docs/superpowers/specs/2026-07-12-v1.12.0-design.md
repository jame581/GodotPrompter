# v1.12.0 Design — "Adventure & Ecosystem II"

**Status:** Approved (brainstorming complete 2026-07-12)
**Author:** Jan Mesarč
**Predecessor:** v1.11.1 (limboai pin bump to v1.8.0, shipped 2026-07-12)

## Summary

A feature release with five independent workstreams shipped together:

1. **Token-budget trim pass** — bring the 9 skills currently over the 16 KB budget back under,
   by micro-trimming in place (no new reference files).
2. **Validator hardening** — promote `token-budget-exceeded` from warning to **error**, plus a
   new advisory warning band for skills approaching the budget.
3. **New `popochiu` skill** — the point-and-click adventure framework (third-party addon #3).
4. **New `dialogue-manager` skill** — nathanhoad's Dialogue Manager (third-party addon #4).
5. **New `phantom-camera` skill** — ramokz's Phantom Camera (third-party addon #5).

The repo grows from **51 → 54 skills**; the Third-Party Addons category grows from 2 to 5.
Repo-wide Godot baseline stays **4.3+**; each addon skill carries its own minimum in its header
line (as `limboai` already does). Validator target: **0 errors**. `csharp-parity-accepted`
warnings grow by the number of GDScript sections in the two GDScript-only addon skills'
SKILL.md files (popochiu, phantom-camera — both added to `GDSCRIPT_ONLY_BY_DESIGN`);
`dialogue-manager` ships full C# parity and adds none.

**Version rationale:** all workstreams are additive (new skills, stricter-but-green validator);
minor bump to `1.12.0`.

## Goals

1. Restore and then *enforce* the 16 KB token-budget rule so it cannot silently regress again
   (it drifted before v1.11.0 and made that release's notes stale).
2. Extend the third-party addon category beyond AI behavior addons into three of the most-used
   gameplay addons: adventure framework, dialogue, camera.
3. Keep the cross-reference graph and agent routing coherent: each new addon skill links to and
   from the core skills it overlaps with (`dialogue-system`, `inventory-system`, `save-load`,
   `camera-system`), and agent descriptions route to them.

## Non-goals (YAGNI)

- A dedicated adventure-game agent (`godot-adventure-dev`) — light-touch routing edits to
  existing agents only.
- Further addons (GodotSteam, Dialogic, etc.) — future releases.
- Covering Popochiu's `develop` branch features — the skill pins the released `v2.1.1` tag.
- C# parity for GDScript-only addons (popochiu, phantom-camera) — same stance as beehave.
- Raising or restructuring the 16 KB budget itself.

---

> **Addendum 2026-07-13 (CRLF discovery):** the "9 skills over budget" premise below was based on local byte counts from this Windows checkout (`core.autocrlf=true`), which over-report by ~1 byte/line. On LF-normalized bytes **no skill exceeds 16,384 B** — all nine sit in the 15,872–16,383 advisory band. §1 is therefore a *headroom* trim (clear the advisory band), and §2 additionally requires the validator (and `count-tokens.mjs`) to **LF-normalize before measuring** plus a `.gitattributes` pinning `eol=lf`, so local and CI numbers agree permanently. Task ordering flips: validator hardening lands first (safe pre-trim on LF bytes) and becomes the measuring tool for the trim. See the implementation plan's Global Constraints.

## 1. Trim pass

Targets (validator output, 2026-07-12): `localization` 16.4 KB, `gdscript-patterns` 16.3,
`godot-ui` 16.3, `assets-pipeline` 16.2, `shader-basics` 16.2, `3d-essentials` 16.1,
`multiplayer-basics` 16.1, `event-bus` 16.0, `input-handling` 16.0.

Method: **micro-trim in place** — tighten prose, dedupe repeated caveats, compress checklist
phrasing. No teaching content removed; no new reference files by default. Per the established
size-check practice, if a specific skill cannot lose the needed bytes without compromising
teaching, fall back to Pattern X relocation *for that skill only* (record it in the plan).

Targets after trim: every SKILL.md **< 16 KB** (hard, becomes a validator error this release);
aim for **≤ 15.5 KB** where achievable so skills also clear the new advisory band. Skills that
land in 15.5–16.0 emit the advisory warning — acceptable, count recorded in the release notes.

## 2. Validator hardening (`scripts/validate-skills.mjs`)

- `token-budget-exceeded` (≥ 16 KB): **warning → error**. CI (`release.yml`) already fails on
  validator errors, so an over-budget skill now blocks release tags.
- New advisory warning `token-budget-approaching` at **≥ 15.5 KB**: early signal before the
  hard wall. Advisory only — never fails CI.
- Add `popochiu` and `phantom-camera` to `GDSCRIPT_ONLY_BY_DESIGN` so their GDScript-only
  sections emit intentional `csharp-parity-accepted` warnings (beehave precedent).

## 3. `popochiu` skill

**Pin:** Popochiu `v2.1.1` · Godot 4.6 · MIT · GDScript-only ·
https://github.com/carenalgas/popochiu

**Research source:** local clone at `C:\Users\jame_\source\repos\Godot\popochiu` — read at the
`v2.1.1` tag via `git show`/temp worktree (the clone sits on `develop`, which is ahead of the
release; do not switch its branch). Official docs (https://carenalgas.github.io/popochiu/) as
secondary source. Research note: `docs/superpowers/notes/<date>-popochiu-research.md`, dated when the research
runs (limboai-research pattern).

**Core SKILL.md (≤ 16 KB):**

1. *When to use Popochiu* — decision table vs. hand-rolling with core skills
   (`dialogue-system` + `inventory-system` + `state-machine`); Popochiu wins for the full
   AGS/PowerQuest-style workflow with editor tooling.
2. *Install & project setup* — AssetLib/GitHub install, plugin enable, setup wizard, what the
   dock generates (`game/` structure).
3. *Core concepts & one-letter autoloads* — `E` (engine), `C` (characters), `R` (rooms),
   `D` (dialogs), `I` (inventory), `G` (GUI), `A` (audio); Room → Props / Hotspots / Regions /
   Walkable Areas / Markers model.
4. *Rooms & navigation* — room creation, `queue()`-based cutscene scripting, transitions,
   character movement.
5. *Interactions* — clickable scripts (`_on_click`, command pattern), props vs hotspots, GUI
   command framework at a glance.
6. *Characters & dialog basics* — character creation, emotions, entry points into dialog trees.
7. *Implementation checklist.*

**references/ (Pattern X):** `dialogs.md` (trees, branching, conditions), `inventory.md`
(items, combining, using items on scene objects), `gui.md` (shipped GUI templates — 9-verb,
Sierra, 2-click — and customization), `pipeline.md` (Aseprite importer, audio management,
save/load specifics).

**Wiring:** related-skills cross-refs both ways with `dialogue-system`, `inventory-system`,
`save-load` (+ `2d-essentials` if natural); README third-party table row; routing mentions in
`godot-game-dev` / `godot-game-architect` agent descriptions.

## 7. Release mechanics

Standard sequence: `node scripts/bump-version.mjs 1.12.0` (auto-syncs the "54 domain-specific
skills" manifest text), CHANGELOG section, commit, tag `v1.12.0`, push with tags. Reset local
sibling marketplace clones before pushing; the release workflow opens the two marketplace PRs
(skillsmith + legacy), which need manual approval.

## Execution notes

The five workstreams are mutually independent. The three addon skills parallelize cleanly
(subagent per skill is an option at plan time); trim pass and validator change are small and
sequential-friendly. Suggested order in the plan: validator + trim first (so the stricter rule
is green from the first commit), then addon skills.
