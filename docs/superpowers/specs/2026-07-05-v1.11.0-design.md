# v1.11.0 Design — "Godot 4.7 Alignment"

**Status:** Approved (brainstorming complete 2026-07-05)
**Author:** Jan Mesarč
**Predecessor:** v1.10.0 (Ecosystem & Abilities — 3 skills + Third-Party Addons category + Antigravity platform, shipped 2026-06-17; v1.10.1 docs patch shipped 2026-06-27)

## Summary

An **alignment release**, not a new-skills release: sweep all 51 skills, 9 agents, and repo
docs for **Godot 4.7** (released 2026-06-18) deltas. The repo-wide minimum stays **Godot
4.3+**; every 4.7 feature lands as an additive section or note annotated `(Godot 4.7+)`,
exactly like 4.5/4.6 content did in v1.4.0/v1.5.0. Skill count stays **51**.

Unlike 4.6 (whose IKModifier3D family justified new skill sections wholesale), Godot 4.7's
biggest new subsystems — **Vulkan raytracing** (RenderingDevice BLAS/TLAS/RT pipelines) and
**DrawableTexture2D** — are officially marked *experimental*. They get one-line "experimental
in 4.7, not yet recommended for production" mentions in the nearest existing skill, and no
recipes. The stable 4.7 additions (AreaLight3D, VirtualJoystick, joypad motion sensors,
BlendSpace SyncMode, one-way collision direction, Java-interfaces-from-GDScript, HDR output,
AccessibilityServer, and others) are absorbed into existing skills.

The release replays the proven **v1.5.0 "Godot source alignment" method**: a verified
per-skill delta inventory note first, then a skill-by-skill apply pass. Research is grounded
in the local clones — `D:/Godot/godot` (engine, `CHANGELOG.md` §4.7) and `D:/Godot/godot-docs`
(master, includes `upgrading_to_godot_4.7.rst` and the 4.7 class reference) — not in web
searches or model memory.

**Version rationale:** Purely additive documentation updates to existing skills (new annotated
sections, behavior-change warnings, stale-text fixes). No new skills, no structural changes,
no breaking changes for consumers → minor bump to `1.11.0`, consistent with the
v1.5.0→v1.10.0 cadence.

## Goals

1. Every stable, script-facing Godot 4.7 feature that belongs in an existing skill's domain is
   documented there with a `(Godot 4.7+)` annotation, GDScript-first with C# parity.
2. Every **silent 4.7 behavior change** that can break a reader's project (the highest-value
   content this cycle) is called out as a warning note in the skill where readers would hit it.
3. Stale claims invalidated by 4.7 (changed defaults, "not possible" statements, old
   signatures) are corrected repo-wide.
4. Agents, README, and manifests reflect 4.7 awareness without inflating scope.
5. The delta inventory note doubles as durable release documentation, like
   `2026-04-30-godot-4.5-4.6-deltas.md` did for v1.5.0.

## Non-goals (YAGNI)

- **No new skills.** Raytracing is the only near-candidate and it is experimental; a dedicated
  skill is deferred until the API stabilizes (likely 4.8+).
- **No recipes for experimental subsystems** (raytracing, DrawableTexture2D) — mention-only.
- **No minimum-version bump.** The 4.3+ baseline promise in README and all skills stands.
- **No migration/upgrade meta-skill** — considered and deferred; 4.7 behavior changes are
  documented in-domain instead.
- **No editor-only feature coverage** beyond skills whose domain *is* the editor
  (`addon-development` gets the new plugin APIs; the 2D scene painter, dock overhaul UX, and
  similar editor conveniences are out of scope for gameplay skills).
- **No new agents**; light routing-text edits only.
- **No exhaustive bug-fix documentation** — only fixes that change documented behavior
  (e.g. `NavigationServer3D.map_get_closest_point_normal` normalization) qualify.

## Phase 1 — Delta inventory note

Author `docs/superpowers/notes/2026-07-05-godot-4.7-deltas.md` in the same table format as the
4.5/4.6 note:

| Skill | Feature | Source | New/updated section proposed |
|-------|---------|--------|------------------------------|

**Verification rule:** every row is confirmed against the local godot-docs clone (class
reference `.rst` under `classes/`, or `tutorials/migrating/upgrading_to_godot_4.7.rst`) or the
engine `CHANGELOG.md` PR link *before* the row is added. The changelog survey that seeded this
design is starting material, not a source of truth. Rows that cannot be verified are dropped,
mirroring the 4.5/4.6 note's policy.

Rows are one of three kinds:

1. **New API section** — a 4.7 feature worth a new annotated section or subsection.
2. **Behavior-change warning** — a silent change folded into an existing section as a short
   warning note (these carry the migration-guide citation).
3. **Stale-text fix** — existing skill text that 4.7 invalidated.

Per-edit rules (unchanged house style):

- GDScript example first, then C# equivalent, within each new section.
- `(Godot 4.7+)` annotation in the section title or as a note prefix; behavior-change warnings
  cite the migration guide.
- Cross-references verified; any SKILL.md pushed over 16 KB gets the Pattern X treatment
  (deep-dive moved to `references/` with back-link).
- `node scripts/validate-skills.mjs` run after each skill; must stay 0 errors / 13 accepted
  warnings throughout.

## Validation & testing

1. Validator green throughout: **0 errors, 13 warnings** (the pre-existing
   `csharp-parity-accepted` allowlist); any new warning is a regression to fix in-release, not
   allowlist.
2. All new code examples grounded in the local godot-docs class reference — API names,
   signatures, enum values copied from the `.rst`, never from memory.
3. Every inventory row either applied (`[done]`) or explicitly dropped with a reason before
   release.
4. Agent integration spot-checks per `tests/agent-integration/TEST_PLAN.md` only if agent
   files change materially (expected: routing text only, no re-run needed).

## Release

Standard flow (CONTRIBUTING.md): work on `feature/v1.11.0` branch → bump + changelog → PR →
merge → tag `v1.11.0` → `.github/workflows/release.yml` validates, creates the GitHub release,
and opens marketplace PRs (skillsmith primary + legacy godot-prompter-marketplace).

## Risks & mitigations

- **Survey drift** — the seeding changelog survey may contain misread items. Mitigated by the
  Phase 1 verification rule (no unverified row enters the inventory).
- **Token-budget regressions** — high-traffic skills (`physics-system`, `godot-ui`,
  `animation-system`) are already near 16 KB. Mitigated by Pattern X moves as part of the same
  edit, per house recipe.
- **Experimental API churn** — avoided by mention-only policy for raytracing and
  DrawableTexture2D.
- **C# parity gaps** — every new section needs a C# block unless the skill is on the
  GDScript-only allowlist; parity is enforced by the validator at each step.
