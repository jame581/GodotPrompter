# Godot 4.8 Editor Check — mentor editor references (4.8-beta3)

v1.17.0 Task C3 (v1.15.0 follow-up 2(d)). Re-checks every recipe in
`skills/godot-mentor/references/editor-recipes.md` and every section of `editor-navigation.md`
against Godot **4.8-beta3**, and re-checks the three 4.7 claims of follow-up 2(a).

**4.8 is not stable.** Every verdict below was checked on 4.8-beta3. Re-check the "changed" rows,
and diff the label sets again, once `4.8-stable` is tagged (timing gate of the v1.17.0 plan).

## Method

- **Engine source.** `godotengine/godot` at **`c51ff06e8836a70ea905701c081bf94124dcd6ce`** (the
  commit the 4.8-beta3 build was made from; see `2026-11-11-godot-4.8-deltas.md`), compared with
  tag `4.7.2-stable` (`ed1daf0bf001`). Citations write the beta3 commit as **`b3:`** and 4.7.2 as
  **`472:`**, then `path:line`. Sparse checkouts of `editor/`, `modules/`, `core/input/`, `main/`
  and `doc/classes/` in the session scratchpad; nothing cloned into the repo.
- **Label sweep.** Every bold label in both reference files (290 unique strings) was grepped as a
  string literal in the `.cpp`/`.h` files of `editor/`, `modules/` and `scene/gui/` at both refs.
  No label present at 4.7.2 is missing at beta3. 50 labels changed occurrence count; each was
  traced, and only the ones listed under "Changed" are real UI changes (the rest are new uses of
  common words, the TileMap editor moving to `modules/tilemap/`, or accessibility names).
- **Per-file string diff.** The translatable strings (`TTR`/`TTRC`) of the 23 files behind the
  recipes were diffed between the refs: connections dialog, Signals and Groups docks, Input Map
  and Event Configuration, AnimationPlayer and track editor, SpriteFrames, Import dock, export
  window and template manager, resource picker, Theme editor, asset library, Attach Script
  dialog, Inspector dock, autoload settings, plugin settings, profiler, TileSet/TileMap editors.
- **Headless editor tree probe.** An enabled `EditorPlugin` in a scratch project walked the editor
  tree of the headless 4.8-beta3 binary and of the installed 4.7.2 (`godot`), printing tab
  titles, menu items and button texts. It confirms that controls exist with those texts; it does
  **not** show what the editor looks like, and nothing here was seen on a display.
- **Draft migration guide** (godot-docs PR #12421, `mg48:`) used only for corroboration.
- The 4.8 **docs** were not checked (4.8 has no docs branch yet). Sentences in the references
  about what "the docs" say stay scoped to the versions they were checked on.

## Main screens became docks — what a user sees

GH-113051. At beta3 the main screen is `EditorMainScreen`, a `DockTabContainer` for slot
`DOCK_SLOT_MAIN_SCREEN` (`b3:editor/editor_main_screen.cpp:182-201`), and **2D**, **3D**,
**Script**, **Game** and **Asset Store** are `EditorDock`s whose default slot is the main screen
(`b3:editor/scene/canvas_item_editor_plugin.cpp:3929-3934`,
`b3:editor/scene/3d/node_3d_editor_plugin.cpp:3376-3381`,
`b3:editor/script/script_editor_plugin.cpp:4766-4770`, `b3:editor/run/game_view_plugin.cpp:1557-1561`,
`b3:editor/asset_library/asset_library_editor_plugin.cpp:2211-2216`).

- **Still at the top, same names, same order.** The container's tab bar is placed as the title
  bar's centre control (`b3:editor/editor_node.cpp:9076-9078`, moved beside the left spacer at
  `:9317`), centre-aligned (`b3:editor/editor_main_screen.cpp:95-96`). The default layout orders
  the slot 2D, 3D, Script, Game, Asset Store (`b3:editor/editor_node.cpp:9842-9853`). Probe:
  `EditorTitleBar/HBoxContainer/TabBar` = ["2D", "3D", "Script", "Game", "Asset Store"]. On
  4.7.2 the same texts are `Button`s under `EditorTitleBar/EditorMainScreenButtons`. The buttons
  are now tabs, shown as text and icon by default (editor setting
  `interface/editor/docks/main_screen_dock_tab_style`, `b3:editor/settings/editor_settings.cpp:489`;
  icon only on the Android editor).
- **No "3 vertical dots" button on the main screen** (`set_popup(nullptr)`,
  `b3:editor/editor_main_screen.cpp:101`), but **right-clicking a tab opens the dock popup**
  (`b3:editor/docks/dock_tab_container.cpp:217-227,369`): **Dock Position**, **Make Floating**,
  **Close** (`b3:editor/docks/editor_dock_manager.cpp:983-1036`). The draft guide says the
  Script editor's Make Floating is now reached this way (`mg48:173-174`).
- **Can float, cannot move to the sides.** 2D, 3D, Script and Asset Store allow
  `DOCK_LAYOUT_MAIN_SCREEN | DOCK_LAYOUT_FLOATING`; Game allows only the main screen, so its
  **Make Floating** is disabled with the tooltip **This dock does not support floating.**
  (`b3:editor/docks/editor_dock_manager.cpp:948-956`). Slots of other layouts are unavailable in
  the popup's grid and rejected on drop (`:1111,1174,1190`; `dock_tab_container.cpp:105,161`).
  Side docks cannot enter the main screen either (default `available_layouts` is vertical and
  floating, `b3:editor/docks/editor_dock.h:91`).
- **Closable, and listed in Editor > Editor Docks.** Main-screen docks keep the default
  `global = true` (`b3:editor/docks/editor_dock.h:85`), so **Close** is enabled
  (`b3:editor/docks/editor_dock_manager.cpp:941-947`) and the docks menu lists them
  (`:221-242`). Probe, 4.8-beta3 Editor Docks: Scene, Import, FileSystem, Inspector, Signals,
  Groups, History, Output, Debugger, **2D, 3D, Script, Game**, Audio, **Asset Store**, Animation,
  Shader Editor. On 4.7.2 the same menu has no main screens.
- **Not established:** whether tabs can be reordered by dragging in the title bar (the probe
  reads `drag_to_rearrange_enabled = false` on that `TabBar`, but docks are dragged by the dock
  manager, not the tab bar); how a floating main screen looks; the popup's **Move Tab Left/Right**
  arrows on the main screen. The references say only what is listed above and that "other ways of
  rearranging them were not researched".
