## 6. Release mechanics

- **The `plugin-bundle` job has never run on a real tag.** v1.16.0 is its first. After tagging,
  confirm the branch holds the 295-file bundle and that `npm test`'s file-count check matched what
  the job committed.
- Marketplace PRs (skillsmith and the legacy repo) are opened by `release.yml` when
  `MARKETPLACE_TOKEN` is set; the bump script found neither sibling clone locally. From v1.16.0
  they also switch the entry's source to `"ref": "plugin-bundle"`. **Verified 2026-10-22:** the
  bump snippet and `sync-marketplace-readme.mjs` were dry-run on fresh clones of both repos (both
  pass `claude plugin validate`); Claude Code (`CLAUDE_CONFIG_DIR`) and Copilot CLI
  (`COPILOT_HOME`) each installed `godot-prompter` from a test marketplace pointing at
  `plugin-bundle` (then at the 1.15.1 bundle); the release job's commit step, dry-run without the
  push, fast-forwards the branch and the result validates. **Update path verified 2026-10-22:** with
  throwaway config directories and a test marketplace served over git, both hosts updated an
  install made from today's entry (`master`, 1.15.1) to an entry with `"ref": "plugin-bundle"`
  (the locally built 1.16.0 bundle): Claude Code 1.15.1 → 1.16.0, Copilot CLI v1.15.1 → v1.16.0
  (59 skills). The installed SessionStart hook emits the card, with the three new skills, in a
  folder with `project.godot` and nothing outside one. **Not verified:** the same against the real
  GitHub marketplaces — after the marketplace PRs merge, run `claude plugins update godot-prompter`
  and `copilot plugin update godot-prompter` and check the new skills appear.
- **The marketplace `ref` follows a moving branch.** Once tag X+1 publishes its bundle, entries
  still saying version X install X+1 content until the bump PR merges. Accepted for now; pinning
  would need a per-release bundle tag (e.g. `bundle-vX`) used as the `ref`.
- **The session card has 1 byte of headroom** (3,071 of 3,072). The next card edit must free bytes
  first. v1.16.0 dropped "Skills carry trade-offs — surface them." from the report rule; the
  in-project grill cases were re-run on 2026-10-22 (`evals/GRILL.md`, "v1.16.0 card check"):
  grill-05 fired `godot-grill` 0/3 on the new card and 1/3 on the old card, down from 4/5 on
  2026-10-09, and the without arm fell from 0.87 to 0.33 as well — drift outside the card. Re-baseline
  grill-05 at 5 runs per arm before the next card change. skill-16 still fires `web-services` 1/3;
  it runs without the card, so the fix has to be in the skill's description.
